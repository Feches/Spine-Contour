# Spine Contour 1.0.8

Films named to a simple pattern now load with their subject, timepoint, film date and a
note already filled in; the paired CSV export handles a follow-up series and two films
from the same day; and a study is shown by its file name everywhere, with the internal
record id retired from view. This release includes 1.0.7's changes unchanged.

## Naming films

Name a file `subject_timepoint_date.jpg`, with an optional note at the end, and the app
reads those fields when the film is loaded, whether through the Workspace folder load,
**Choose radiograph** or a drag and drop:

```
sub225_pre-op_10-23-2023.jpg
sub225_post-op_3-22-2024.jpg
sub225_pre-op_10-23-2023_femoral heads.jpg
```

Underscores separate the fields. The subject comes first; a timepoint (`pre-op`,
`post-op`, `intra-op`, `6 wk`, `1 yr`, …), a film date (`3-22-2024` or `2024-03-22`)
and a view (`flexion`, `supine`, …) may follow in any order; anything else after them is
the note. Spaces and hyphens inside a field are part of it, so `post op` and `post-op`
both read as Post-op. A name with no recognisable field is taken whole as the subject,
as before. `docs/naming-films.md` is the full guide, with the words the app recognises
and the names that do not work.

Loading still fills only blank fields. A film loaded by an earlier version with its
whole name stored as the subject keeps that subject: delete it on the Find tab and load
the folder again.

## The note

Each study gains a **Note**: a fifth column in the study drawer's Study group on the
Analysis screen, editable like the others, exported in the CSV after Film date and
searched by the Find box. It is what tells apart two films of the same subject taken
on the same day, such as one centred on the femoral heads.

## Paired export by visit

The paired CSV no longer needs a different timepoint label for every visit. A visit is
one subject, one label, one film date; when a subject has several visits on a label
they are written as `Post-op 1`, `Post-op 2` and so on in date order, each with its
film date column, and a subject with fewer visits leaves the rest blank.

Two films on the same visit merge when exactly one of them carries a note. The film
without a note leads; the noted film only supplies the measurements the first lacks.
Every merge is flagged: the export's message names the merged visits and the values it
set aside, and the file gains a `disagreements` column beside each visit listing the
measurements the two films disagreed on. A merged visit's PI-LL mismatch is computed
from its merged PI and LL, and a `derived across films` column says which film supplied
each when they came from different films. Two same-day films that both carry a note or
both lack one, and two pre-op visits on different dates, still leave the subject out of
the file with a message saying why.

## Names everywhere

The Find list shows a study's full name, wrapping a long one onto more lines instead of
cutting it off, and formats it exactly as the Parameters grid does. Both CSV exports
name a film by its study name, the file name without its extension, under `Study ID`,
which is also the value a clinical spreadsheet's `study_id` column must hold to match a
film on import. The `SP-nnnn` record id appears nowhere a person looks: not in the
files and not in the tooltips over a name. With the sidebar collapsed, the open-study
card becomes an icon button that carries the name in its tooltip.

## Installation

The release provides Windows x64 and macOS Apple Silicon installers plus
`SHA256SUMS`. In-app updating is not included; install the new version over the
existing app. Studies and settings remain in the existing application profile.
The macOS app remains unsigned.
