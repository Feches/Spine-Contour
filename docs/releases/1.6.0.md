# Spine Contour 1.6.0

This release carries PR #77: the measurement pipeline goes back to the one 1.4.0 had, with fine-tuned models in it.
1.5.0's fixed seven-measurement pipeline is removed. A film segmented before 1.6.0 keeps its result until it is run
again; a new run uses this pipeline and these models and may give different numbers.

## The pipeline

- Lumbar, cervical and full-spine films are read by 1.4.0's regional paths: crop search, the S1 detector and the
  lumbar landmark model on a lumbar film, the anatomical cervical model on a cervical film, and both on a full-spine
  film. 1.5.0's subpixel decoders, its per-measurement routes (`geometry.measurement_sources`) and its graphs
  `lumbar_heatmaps` and `cervical_slope_hrnet` are removed.
- On a full-spine film the neck is now located with the same anatomical cervical model a cervical film uses, in place
  of the image-sided cervical HRNet. Its anterior and posterior points keep their identity when the film is mirrored;
  crop agreement and the orientation thresholds are unchanged.
- **Settings → Processing → Crop localizer** Off skips the crop search on a lumbar film again, and **Toolbar removal**
  removes a detected bottom PACS toolbar again, as before 1.5.0. A lumbar result carries the U-Net body mask again.
- The CPU/DirectML runtime of 1.5.1 stays, with a processor saved as `cuda:GPU-…` read as CPU.

## Models

| Model | 1.4.0 | 1.5.x | 1.6.0 |
| --- | --- | --- | --- |
| S1 detector (Keypoint R-CNN) | original | fine-tuned | fine-tuned, as 1.5.x |
| Anatomical cervical HRNet | original | fine-tuned, epoch 16 | fine-tuned, epoch 16, with the original decoder |
| Lumbar landmark HRNet | original | fine-tuned, epoch 1 | an updated checkpoint (PR #77, `129dc01`) |
| U-Net vertebral model | original, default | removed | original; HRNet is the default |
| Femoral U-Net, cervical detector | original | original | original |
| Region detector, view classifier | original | fine-tuned region detector | original |

The vertebral model is a choice in **Settings** again: HRNet, the default, or U-Net. The lumbar HRNet checkpoint is
different from both 1.4.0's and 1.5.x's, and PR #77 gives no training notes or measurements for it. 1.5.0's training
notes for the other fine-tuned weights are kept at the `v1.5.0` tag:
[annotated-data fine-tuning](https://github.com/Feches/Spine-Contour/blob/v1.5.0/docs/annotated-finetuning.md).

## Results from 1.5.0 and 1.5.1

A film segmented by 1.5.0 or 1.5.1 keeps its stored result and reads as it did: the Analysis header labels its model
HRNET, a cervical film keeps its cervical review reasons (without this, it would have been told to check an S1 endplate
it does not have), and PT and Global SVA are drawn, and Global SVA computed, from the anchors those values were
measured with. Editing such a film measures it again from the shared S1, hip and C7 points, the only ones this
pipeline reads. Run it again to read it with 1.6.0's pipeline and models.

## Verification

1,258 desktop tests on the merged tree (1,253 in 1.5.1; five new ones cover 1.5.x results: the model label, the
review reasons, the per-measurement anchors for drawing and for Global SVA, a moved anchor taking precedence, and the
re-measure dropping the anchors). PR #77's checks passed on its head: the Windows and macOS release builds, each
running the backend and renderer suites and verifying the packaged models. PR #77 reports 774 backend tests passing on
its validation server and 142 more on Python 3.12; the full-spine neck adapter matching the standalone cervical
model's coordinates on five real films; and five real full films through the API, of which one gave cervical and
lumbar landmarks, two cervical only, and two no result because the automatic orientation was uncertain. These show the
pipeline runs as intended, not that it is more accurate. Not done: the Windows GPU (DirectML) check that PR #77's
author asked for before release, a reproduction of the GPU failure reported against 1.5.0, and the smoke suites. These
are software checks, not clinical validation. The release workflow runs the backend and renderer suites and builds and
verifies the Windows and macOS installers before publication; merging the release PR to `main` publishes v1.6.0.

## Compatibility

No store version bump. The study record, the label record, the CSV exports and the bundles keep their format, and a
library written by 1.5.1 loads with its results read as described above. Opening a library 1.6.0 has written in an
earlier build was not tested. The macOS build remains unsigned.
