# Spine Contour 1.0.13

This release combines two pull requests from 2026-10-01. PR #50 gives a failed
segmentation attempt its own status, colours full-spine and cervical outlines like
lumbar ones and removes five advisory lines under CVA. PR #49 adds a trained crop model
as an optional alternative to the crop search. Crop search stays the default, and with
it the existing models and processing are unchanged.

## Failed status

Before this release, a film whose automatic film detection or orientation failed during
a batch kept reading **Processing**, as though it had never been run (issue #39). A
failed attempt now leaves a **Failed** status, and the error is shown in the badge's
tooltip on the Find list and in the Analysis header. This applies to single runs and
batch runs, and the failure is saved with the study.

- On the Find tab, sorting by status puts Failed first. The summary line counts Failed
  studies as unsegmented.
- Batch segmentation offers Failed studies again, including a study whose earlier run
  succeeded but whose latest re-run failed.
- **Mark reviewed** is unavailable on a Failed study ("Rerun segmentation after the
  failed attempt").
- A failed re-run keeps the earlier measurements on screen and in the exports, but the
  study reads Failed until a run succeeds.
- Retrying shows Processing. A successful run, or changing the study's region or
  anterior side, clears the failure.
- Running a cervical film before its anterior side is chosen also reads Failed until
  the side is chosen.
- Cancelling a run is not a failure: the previous results and status are kept.

## Outline colours

Vertebral outlines are now drawn in the level colour palette on every film, so
full-spine and cervical studies match the lumbar ones (issue #38). C2 has its own colour,
and C3–C7 reuse the L1–L5 colours. The selected level is still highlighted as before.
Lumbar outlines, which were drawn in a dark line over the coloured overlay, now use the
level colours as well.

## CVA warnings

Under CVA (cervical and full-spine studies), the Measurements panel no longer shows
these five lines (issue #46):

- Review the automatically detected film region and orientation before accepting
  measurements.
- Manually edited landmarks — verify the corrected positions.
- Verify the C7 centroid, S1 endplate and selected anterior image side.
- Review C7 identity, the S1 posterior corner, image orientation and calibration before
  accepting global SVA.
- Anterior orientation was selected automatically from regional crop agreement; confirm
  it before accepting measurements.

Every other warning is still shown. The review status is unchanged: these conditions
still mark a study Needs review, so a CVA study can read Needs review with no line under
the measurements. Lumbar studies show all of their warnings as before.

## Crop method

**Settings → Processing → Crop method** offers **Crop search** (the default, the existing
behaviour) and **Trained model**. Trained model runs a bundled ONNX region detector once
on the film. On full-spine films it proposes the cervical and lumbar crops; on lumbar
films it proposes the lumbar crop when Crop localizer is On.

A proposal is not accepted anatomy. The existing landmark and agreement checks still
decide whether a region is established. A region whose proposal is missing or fails those
checks falls back to Crop search, and a region can still remain unconfirmed. Each result
records which method supplied the crop, the proposed boxes and why any fallback ran. The
region detector runs on the CPU whatever the Processor setting. Cervical-only runs do not
use a crop method.

The setting is saved with the other processing preferences. Preferences saved by earlier
versions read as Crop search. See [inference implementation and
validation](../onnx-inference.md).

## Checks

The renderer unit tests pass on this tree: 587, including new tests for the Failed
status, batch retry, status sorting, outline colours, the CVA warning filter and the crop
method setting. Each pull request passed the full Windows and macOS build workflow on
its own: backend tests, renderer tests, the packaged backend and the check that every
bundled ONNX model, the crop detector included, loads and runs. The workflow on this
release's pull request repeats those checks on the combined tree. The app was not
launched from source on this tree. These are integration checks, not a clinical
accuracy benchmark of the trained crop model.

## Installation

The release provides Windows x64 and macOS Apple Silicon installers plus
`SHA256SUMS`. In-app updating is not included; install the new version over the
existing app. Studies and settings remain in the existing application profile.
The macOS app remains unsigned.
