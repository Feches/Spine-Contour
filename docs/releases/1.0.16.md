# Spine Contour 1.0.16

This release retires the trained automatic crop method that 1.0.13 added (PR #49) and
returns every run to Crop search (PR #57). There is no measurement change; the weights are
unchanged from 1.0.15.

## Crop method

- **Settings → Processing → Crop method** shows **Crop search** as a fixed value. The
  **Trained model** button is gone.
- A preference saved as Trained model by 1.0.13–1.0.15 is read as Crop search when the app
  starts, and the processing backend runs Crop search for any request that still names
  the trained method. Neither path can keep the retired method running.
- Crop search locates the cervical and lumbar regions on full-spine films, and the lumbar
  region on lumbar films when **Crop localizer** is On. Crop localizer On/Off, automatic
  film detection and the existing landmark and agreement checks are unchanged.
- The crop-detector graph is still bundled and still checked by
  `spine-contour-backend.exe --verify-models`, but no run uses it.

Results segmented with Trained model before this release keep what they recorded. Run
segmentation again to read such a film with Crop search.

## Checks

PR #57 ran 16 desktop processing tests and 75 backend crop, full-spine and server tests.
The release workflow runs the full renderer and backend suites on Windows and macOS before
it publishes. These check routing and compatibility, not segmentation accuracy: no new
real-image validation was run for this release. They are software checks, not clinical
validation.
