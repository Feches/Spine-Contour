# Spine Contour 1.5.1

This release carries PR #74, which takes GPU processing back to the 1.4.0 runtime after reports of processing failures
with 1.5.0's GPU additions. The fine-tuned models, the subpixel decoders and the measurement routes that 1.5.0 brought
are kept unchanged, so a film gives the same result as on 1.5.0.

## GPU processing

- Removed: the CUDA runtime and its NVIDIA device list, the adaptive crop batches that halved after an out-of-memory
  error, the out-of-memory retries that released other models, and the four-image S1 detector graph
  (`backend/onnx/s1_batch.onnx`). `backend/gpu_batch.py`, `backend/requirements-cuda.txt`, `tools/export_s1_batch.py`
  and `tools/probe_cuda_oom.py` are gone.
- Every model call runs one crop at a time, the lumbar heatmap and global-SVA landmark graphs included, and a
  cancelled run stops before the next call. The model session cache holds four models again, as in 1.4.0.
- On Windows, a DirectX 12 GPU still runs the models through ONNX Runtime's DirectML build only after its outputs pass
  the parity check against the CPU, and a GPU error still runs the film again on the CPU. macOS runs on the CPU. See
  [GPU processing](https://github.com/Feches/Spine-Contour/blob/main/docs/gpu-processing.md) and
  [fixed measurement pipeline](https://github.com/Feches/Spine-Contour/blob/main/docs/fixed-pipeline.md).
- A processor saved as `cuda:GPU-…` by the 1.5.0 NVIDIA preview is read as **CPU** when the app starts; the other
  processing settings (mode, threads and the rest) are kept.
- A result no longer records `qc.processing.batches`.
- The Windows preview workflow builds the DirectML preview installer only. The NVIDIA preview ZIP and the workflow's
  pull-request trigger are removed.

## Verification

1,253 desktop tests on the merged tree (1,252 in 1.5.0; the new one covers the `cuda:GPU-…` migration).
PR #74 reports, on a real full-spine film with the same saved localization before and after the rollback, identical
landmarks, measurements, framing and model identities, with every model call at batch size one; this checks that the
rollback runs the same models the same way, not their accuracy. PR #74's Windows check failed on one backend test,
`test_real_directml_invalid_adapter_aborts_without_fallback`, which the rollback had pointed back at
`backend/onnx/vertebra.onnx`, the lumbar U-Net graph 1.5.0 removed; the release branch restores it to `hrnet.onnx`, as
1.5.0 had it. The reported GPU failure has not been reproduced on Windows GPU hardware, and the smoke suites were not
re-run. These are software checks, not clinical validation. The release workflow runs the backend and renderer suites
and builds and verifies the Windows and macOS installers before publication; merging the release PR to `main`
publishes v1.5.1.

## Compatibility

No change to the study record, the label record, the CSV exports, the bundles or the models. A library written by 1.5.0
loads unchanged, and the other way round. The macOS build remains unsigned.
