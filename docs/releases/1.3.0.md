# Spine Contour 1.3.0

This release is for reviewing a library of films one after another. The arrow keys step through the Find list from the
Analysis screen, the list filters from its column headers with several ticks at once, a REGION column says what each
film is, an imported film's view is Unknown until someone sets it, and an unsegmented lumbar film opens on its X-ray.

## Previous and next

- On the Analysis screen, **Left** or **Up** opens the previous film and **Right** or **Down** the next, in exactly
  the order the Find list shows under its search, its header filters and its sort. Beside **Back** the header carries
  **Previous** and **Next** buttons with the film's place between them, `3 / 42`, so the mouse can do the same and you
  can see where you are; the two are greyed at the ends, and nothing wraps.
- A film the filters hide, such as the one you just marked reviewed while the Status menu was ticked for Needs review,
  reads an en dash in place of its number, and its next and previous still step from where it sat, so marking and
  pressing Right goes straight on down the list. The keys are left alone while a text field, a dropdown or a slider
  has focus and in edit mode, where they nudge handles; with focus left on the Region or Orientation select they
  navigate rather than changing the region, which would have wiped the result.

## Filters in the column headers

- Every Find header but STUDY and DATE has a funnel. It opens a menu of the values in your library with a checkbox
  each, **All** and **None** above them, and the two sort directions below; several ticks at once are allowed (two
  regions, three statuses), within a column any ticked value matches and across columns every column must match.
  SUBJECT's menu is a text box. An active funnel is coloured and shows its number of ticks, with the ticked values on
  its tooltip. Escape, the menu's close button, a click elsewhere or opening a film closes it; the bar's Workspace,
  Folder and Status dropdowns are gone, and the bar keeps the search box, Delete, Export and Segment.
- The **Status** and **Region** menus always list every status and every region, so a tick stays put when its last
  film changes: with Needs review ticked, marking the last Needs review film reviewed leaves an empty list reading
  `No studies match these filters.` with Next greyed, not the whole library. The View, Workspace and Folder menus list
  what the library holds. The filters last for the session, like the sort: a trip to a film and back keeps them, and
  previous / next follow them.

## The REGION column

- Between SUBJECT and VIEW, reading **Unknown**, **Lumbar**, **Cervical** or **Full spine**: the region you set on the
  Analysis screen or in the import table, else the one the run detected, else Unknown. It fills in the moment a run
  finishes, sorts (Unknown last) and filters like the rest. Both CSV exports' `Spine region` cell reads the same
  label, `Unknown` for a film with no run. The Analysis header's meta line agrees.

## The Unknown view

- A film's view — the patient position, Standing lateral, Supine lateral, Flexion lateral and so on — used to default
  to Standing lateral on import, which read wrongly on a cervical film and was too much to set per folder. It is now
  **Unknown** until a folder or file name, the CSV, the import table or the drawer sets it: the import table's VIEW
  selects default to Unknown, the VIEW column, the Parameters grid, the drawer, the Analysis header and the sidebar's
  open-study line read Unknown, the grid's View filter offers Unknown, the CSV writes an empty view cell and reads a
  blank or `Unknown` cell as Unknown. Films already in your library keep whatever view they have.
- An Unknown view no longer blocks segmentation. Only a view you set to something non-lateral is refused before a run;
  the run works out whether the film is cervical, lumbar or full spine, and a film it cannot place fails with its
  reason, as before. The run fills in the region, never the view.

## Unsegmented films

- An unsegmented lumbar film opens on its X-ray, decoded from the original at its default window, with the
  **UNSEGMENTED** notice and its Run segmentation button as a strip along the bottom of the stage instead of a card
  over a dark stage, and window / level available. Auto detect, cervical and full-spine films show the original's
  preview with the run button on the region bar, as before. The region note says when the original cannot be read.
- Opening a film no longer keeps its file bytes for the session, and the preview or decode starts only once you have
  settled on a film, so stepping quickly through many unsegmented films neither fills memory nor queues work for the
  films you passed.

## Fixes

- Ticking a row far down the Studies list scrolled the whole app off the window: the tick box's hidden input sat at
  the list's content coordinates, outside the list's own clipping, and focusing it scrolled the document. Fixed in the
  tick box's style; the document never scrolls now.
- **Back** from a film lands on that film's row, centred in the list, instead of at the top.
- The REGION column had pushed the Find table past the page column's width, cutting off the Delete control at every
  window (the owner's gate found it). The columns' minimum widths are tightened so the table fits again, and on a
  window narrower than the columns the Delete control stays at the table's right edge instead of behind the scrollbar
  at the bottom of the list.

## Verification

1,147 desktop tests (1,110 in 1.2.0; the new ones cover the list's filters, options, normalisation and matching, the
neighbour and position rules, the region key and label, the Unknown view through the gate, the store's validation,
the seeding, the CSV both ways, the batch planner and the bundle's update). A new CDP smoke suite for this screen,
`smoke-reviewer`, read 131/131 on fresh scratch profiles with synthetic films, by DOM and store reads only: the scroll
fix, the header menus (open, tick, All, None, sort, Escape, a click elsewhere, the active count, the end of a filtered
queue), previous / next by key and by button over the list's own order, the region-bar selects yielding the keys, the
REGION column after a run, the import table's Unknown default, the X-ray and its strip, the missing-film note. On
their own fresh launches the other suites read studies 157/157, parameters 58/58, workspace 100/100, seeding 36/36,
persist 42/42 then 55/55, levels (dom) 145/145 and bundle 17/17, 18/18 and 9/9; the global-sva, cervical, accuracy,
onnx-localizer, processing and partial-segmentation suites and the levels film phase need real films or model runs and
were not re-run. The branch had a whole-branch review whose four findings were fixed and re-reviewed before the gate.
The owner's gate on real films passed, with one round of feedback (the table's width) fixed and re-verified. The
backend is unchanged from 1.2.0, so its suite was not re-run. These are software and integration checks, not clinical
validation. The release workflow builds and tests the Windows and macOS installers before publication; merging the
release PR to `main` publishes v1.3.0.

## Compatibility

The study record's `view` may now be absent (`null`) with no store version bump: a store written by 1.2.0 loads
unchanged, and its films keep their views. In the other direction, a library this version has saved with an Unknown
view cannot be opened by 1.2.0, which refuses a record without a view; the same holds for a 1.2.0 library in which a
view had been cleared in the drawer, once this version has saved it. Bundles exported with Unknown views import only
into this version or later (1.2.0 skips those films as malformed); a bundle update keeps your film's view when the
bundle's is Unknown. The list's filters are session-only and never written. The label record and the backend are
unchanged. The macOS build remains unsigned.
