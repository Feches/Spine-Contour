# Spine Contour 1.8.0

This release adds flags on films, and carries PR #86 (set the region of several studies at once) and PR #85 (a new
README). The models and the backend are unchanged.

## Flags on films

- A flag is a short label of your own on a film: 1 to 40 characters, up to 20 per film. A comma, a semicolon or a line
  break ends one, a leading `#` is dropped, and two flags that differ only in capitals are the same flag.
- **Find tab.** A new FLAGS column, last in the list. Click a film's cell to edit its flags in place: type to add, pick
  from the flags already in use, Esc cancels. The column's header menu filters the list by flag (films with any ticked
  flag, or with every one, and `No flags`); the list also sorts by FLAGS and the search box finds a flag.
- **Flag N selected** on the Find bar opens a list for every ticked film: each flag in use shows how many of them hold
  it, a tick puts it on all of them or takes it off, and a new flag can be typed. A segmentation run does not block it.
- **Analysis screen.** A flags block above the comment in the side panel, with the same editor.
- **Parameters tab.** A read-only FLAGS column and a flag dropdown (`All flags`, each flag in use, `No flags`) that
  narrows the grid and so both exports.
- Comments are as they were.

## Flags in the exports, bundles and the label record

- **Export CSV** gains a `Flags` column after `Note`: the film's flags in the order they were added, joined with `; `,
  empty for a film with none. It is always written, so **every column after `Note` sits one place further right** than
  in 1.7.0.
- **Export paired CSV** gains a `<visit> flags` column for every visit, after the film dates.
- **Bundles** carry each film's flags. An import adds the incoming flags to the film's own and never removes one; a
  flag that matches one already in the library takes the library's spelling.
- **The label record** gains an optional `flags` list after `comment`. A change to a film's flags rewrites only that
  list in an existing record: `saved_at`, `app_version` and the annotation are left as they were.

## Set the region of several studies at once (PR #86)

- The Find bar gets **Set region of N…** beside Delete, Export and Flag. It sets Auto detect, Lumbar, Cervical or Full
  spine on every ticked, visible study, as the Analysis screen's Region select does on one film.
- A changed study loses its result, so **Segment N selected** runs it again with the new region. Studies already set to
  that region are left as they are, results included. A film's flags are kept.
- A change that would clear saved results asks first; one that clears nothing applies at once with a message.
- It is unavailable during a run, a batch, a delete or an import, and when studies are not being saved.
- Two changes on top of the pull request: a changed study also loses its crop marks, as 1.7.0's Region select clears
  them; and the prompt reads "1 of their saved results", not "result".

## README (PR #85)

- The README has the website's logo, a table of what each film type measures, an accuracy summary, download and
  quick-start sections, and the detailed usage reference folded into collapsible blocks.

## Verification

On a Windows workstation, on the release tree, from source: 1,328 desktop tests passed. The in-app suites, driven over
the DevTools protocol on a scratch profile with invented films, each on its own launch, all passed: the Find list and
its bar (309 checks), reviewer navigation (180), the Parameters tab (87), the level editor (202), persistence (46, then
60 after a restart), bundles across two profiles (19, 24 and 37), the Region select (16) and a 400-film scale probe
(35). At 400 invented films a keystroke in a FLAGS cell took about as long as one in the search box (61 ms against
59 ms), and a 300-film bulk change reached the list in under a tenth of a second and its 300 label records in under a
second.

Not run on this tree: the backend suite (no backend file changed; the release build runs it), a packaged build, and
anything on real radiographs. These are software checks, not clinical validation. Merging the release PR to `main`
publishes v1.8.0.

## Compatibility

- A library written by 1.7.0 loads unchanged. Flags are a new optional field on the study record (no store version
  change).
- **An earlier version drops flags.** 1.7.0 opening a 1.8.0 library removes its flags the next time it saves, and
  ignores a bundle's flags on import.
- **CSV readers that count columns** see every column after `Note` move by one, and the paired file gains a
  `<visit> flags` column per visit.
- **Label records** keep the schema id `spinecontour.segmentation-label/1` and gain the optional `flags` list. The
  published schema file (`docs/design/level-editor/label-record.schema.json`) allows it; a validator still using the
  earlier file rejects a record that has `flags` until it takes the new one.
- The bundle format (`spinecontour.bundle/1`) is unchanged. The macOS build remains unsigned.

## Known limits

- An import that would take a film past 20 flags keeps the first 20, the film's own first, and does not say so.
- Text left in a flag box is saved as a flag when the window loses focus, as a subject typed in place is.
- A quit partway through a large bulk change can leave some label records with their earlier flags; the library is
  right, and each record is corrected the next time that film's flags change or its record is saved.
- There is no rename: a misspelt flag is fixed by filtering to it and using the Flag list.
