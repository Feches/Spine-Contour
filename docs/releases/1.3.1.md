# Spine Contour 1.3.1

Three fixes to the Analysis screen: the points of the selected level are listed in the edit bar for every placed
level, not only while one is being placed by hand; a region that Auto detect got wrong can be corrected while a batch
runs over the rest of the library (issue #68); and Run segmentation sits in the same place for every region.

## The selected level's points

- Selecting a level in the Vertebral levels panel, or reaching it with Tab, now lists its points as chips in the edit
  bar, each dot in the colour its handle has on the film: `SA SP IA IP` for a vertebral body, `IA IP CENTROID` for
  C2, `ANT POST` for the T1 and S1 endplates, `CENTROID` for T4, and `P1`–`P4` for a femoral head's rim points. Every
  dot is filled (the point is there) and the selected point sits on the accent ground. Before 1.3.1 the chips showed
  only while a level was being placed by hand, so a level the model had found, such as L5, listed nothing when
  selected.
- Clicking a chip selects that point, as pressing its handle or Tab would, so the arrow keys nudge it (1 px; Shift,
  10 px). The help line reads `L5 selected — drag a handle to adjust it, or pick a point and nudge it with the arrow
  keys.`
- Nothing is listed with no level selected, for a level that is unchecked or not yet placed, and while the window /
  level panel is open. A placement in progress keeps its own step chips, which still choose the point the next click
  sets, and once the level is placed the row goes on listing its points.

## Correcting a wrong region (issue #68)

- When Auto detect labels a film wrongly, a cervical film read as lumbar for instance, the Region select on the
  Analysis screen is the way to say so: choosing Cervical clears that result, lists the cervical parameters in the
  Measurements panel and offers Run segmentation. Before 1.3.1 that select, and the Orientation select beside it,
  were disabled with no tooltip whenever any run or batch was in flight anywhere in the library, so a reviewer
  stepping through a library while its batch ran could neither change the region nor the parameters shown.
- Now only the film's own turn locks the two selects (its run in flight, or next up in the running batch), along with
  edit mode and a demo study, each with a tooltip that says so. A run or batch over other films leaves them live.
  Changing the region still clears the film's result and asks for a run, as before; Run segmentation keeps waiting
  for the batch or the current run to finish, and its tooltip now says which.

## Run segmentation in one place

- Since 1.3.0 an unsegmented lumbar film opened on its X-ray with the UNSEGMENTED strip and its Run segmentation along
  the bottom of the stage, while a cervical, full-spine or Auto detect film showed its preview with the button up on
  the region bar. Now every unsegmented film whose film is on the stage, the preview included, shows the strip with
  the button in it, and the region bar keeps View original and the Region and Orientation selects only. A film whose
  preview or X-ray cannot be read keeps the full card with its button, as before, so the stage always offers the run.

## Verification

1,156 desktop tests (1,147 in 1.3.0; five new ones cover the chips for every kind of level, the selected point and
the empty cases, and four cover what locks the Region and Orientation selects: idle, a demo study, edit mode, this
film's run, another film's run, a batch over other films, the film next up, done, later in the queue, and a stopping
batch). The levels smoke suite, `smoke-levels` (phase dom), read 149/149 on a fresh scratch profile with synthetic
films, by DOM and store reads only (145 in 1.3.0; the four new checks read the chips after a level is placed by hand,
a chip click's selection, and a model-placed level's chips with its first point selected). A new suite,
`smoke-region-change`, read 16/16 on a fresh launch: the Region pick on an Auto detect film with a lumbar result when
idle (the preview on the stage and the strip's Run segmentation enabled, the bar offering View original only) and
under a batch over other films (the strip's button waiting with its tooltip), the lock during the film's own turn,
its run, a stopping batch and edit mode, with batches and runs simulated in the store. The reviewer-navigation suite,
`smoke-reviewer`, which covers the rest of the Analysis screen, the lumbar strip and the full card of an unreadable
film included, was re-run on the same launch; its count is in the pull request. The other suites,
the backend and the models are unchanged from 1.3.0 and were not re-run. These are software checks, not clinical
validation. The release workflow builds and tests the Windows and macOS installers before publication; merging the
release PR to `main` publishes v1.3.1.

## Compatibility

No change to the study record, the label record, the CSV exports, the bundle or the backend. A library written by
1.3.0 loads unchanged, and the other way round. The macOS build remains unsigned.
