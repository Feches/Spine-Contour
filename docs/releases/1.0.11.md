# Spine Contour 1.0.11

The models can now run on a GPU. **Settings → Processing → Processor** lists the CPU,
which stays the default and the validated reference path, and on Windows each DirectX 12
graphics card the bundled ONNX Runtime can drive through DirectML; CUDA is not needed. A
card is used only after its outputs have been checked against the CPU, and any GPU
failure reruns the film on the CPU and says so. Every adjacent level, cervical and lumbar,
now reports its segmental lordosis and disc angulation. On standing films the femoral
heads are no longer cut off by the crop chosen for the lumbar landmarks. The model
weights are unchanged from 1.0.10.

## Choosing a processor

Choose the processor in the app, not in Windows' or NVIDIA's graphics settings: a
per-program graphics preference controls drawing, never model inference, and it never
did. The choice is saved as the card's PCI identity, which each run resolves against the
current adapter order; a card that cannot be found or verified is reported and the film
runs on the CPU. Settings retries discovery, and retries again when reopened. Restart the
app after installing a new driver or adding hardware. An integrated GPU can be slower
than the CPU. macOS, including Apple Silicon, keeps the existing CPU path: this release
does not add Apple GPU inference.

## Parity checks and fallback

Before a GPU processes a film, all six models must pass a local numerical check against
the CPU: finite outputs within tolerance, repeated runs, decoded masks and landmark
coordinates that agree, and an ONNX Runtime profile showing that DirectML actually ran
each model. The check can take several minutes. Its verdict lasts for the backend's
lifetime and is keyed to the card, its driver versions, the runtime version and the model
hashes, so a driver update reruns it. A failed check refuses the GPU and processes the
film on the CPU. DirectML vendor metacommands are disabled: the review attached to issue
#40 found them moving a landmark by 2.74 pixels and a measurement by 0.28 degrees on an
Intel UHD 770, and disabling them passed the raw checks on that card and on an RTX 4070.

Any DirectML error discards the whole GPU attempt and processes the original film again
on the CPU, from decoding through measurements, so a result never mixes GPU and CPU
outputs within one crop search or flipped pass. A toast reports the fallback, and the
result records the requested and resolved processor with the reason. The Analysis header
shows GPU, GPU + CPU or CPU from the providers that ran.

These checks use numerical probes, not radiographs, and the release builds run on machines
without a GPU. Physical DirectML qualification and the real-film parity matrix have not
been reported for this revision; the Intel and NVIDIA measurements above are prior
evidence for disabling metacommands, not a validation of every driver. Before relying on
a card, run `spine-contour-backend.exe --verify-models --gpu <id> --parity-films
films.json` on that workstation and inspect the real-film overlays;
`docs/gpu-processing.md` describes the report and its exit codes.

## Segmental lordosis and angulation

Every adjacent level, C2–C3 through C6–C7 and L1–L2 through L5–S1, now reports two
angles in Measurements, and selecting a row draws the two endplates and their extensions
on the film. Segmental lordosis is the angle between the superior endplates of the upper
and lower vertebrae. Segmental angulation, the disc angle, is between the upper
vertebra's inferior endplate and the lower vertebra's superior endplate. L5–S1 uses the
sacral endplate. Both follow the existing Cobb convention: unsigned acute angles with no
lordosis or kyphosis sign. They use the current image calibration, including unequal row
and column spacing, and are computed from the saved geometry, so an endplate correction,
a reset or a reload recomputes them. All detected cervical endplate corners can be
edited. A missing or invalid endplate leaves that value empty; the cervical model does
not predict the C2 superior endplate, so C2–C3 lordosis is unavailable while its
angulation is measured. The Parameters table and both CSV exports carry every value, and
the paired export adds the follow-up change.

The author checked both regions on a real cervical and a real lumbar radiograph with the
shipped models, inspected the constructions and edited endplates through the measurement
endpoint; these are integration checks, not a measurement-accuracy benchmark.
`docs/segmental-angles.md` gives the definitions and the checks.

## Femoral heads on standing films

Standing-film processing reused the crop chosen for the lumbar landmarks to read the
femoral heads, and on real radiographs that crop could bisect a head the film shows in
full. The truncated mask could then fail circle fitting, leaving PI and PT unavailable, or
score a high confidence because the fitter only checked the source image's border. The
femoral stage now expands the crop on the sides its mask reaches, by a quarter of the
crop per pass and at most two extra passes, clipped to the source image. The lumbar
landmarks keep their crop and coordinates, `qc.femoral` records the initial and final
crop windows in source coordinates, and a mask that still reaches the crop boundary caps
the femoral confidence at 0.5 with a review warning. Fit acceptance thresholds and model
weights are unchanged. In the author's checks on six real radiographs, the four
full-spine films retained both heads after the expansion; these are software checks, not
validation against independent reference annotations. `docs/femoral-real-validation.md`
describes the opt-in real-image regression suite.

## Installation

The release provides Windows x64 and macOS Apple Silicon installers plus
`SHA256SUMS`. In-app updating is not included; install the new version over the
existing app. Studies and settings remain in the existing application profile.
The macOS app remains unsigned.
