# Spine Contour 1.0.15

This release refines the Failed status introduced in 1.0.13 (issue #39). Films that have
not been run read Unsegmented, Processing is kept for the films a run or a batch is
working through, Failed has its own red and a dated tooltip, the Analysis screen shows
why a run failed, and the reason is kept as a plain sentence. There is no model,
measurement or processing change; the weights are unchanged from 1.0.13.

## Statuses

- A film with no result reads **Unsegmented**, where it used to read Processing. Its pill
  keeps Processing's grey, with a hollow dot. **Load workspace** adds new films as
  Unsegmented.
- **Processing** now means the film is running or waiting in the running batch. Starting
  a batch turns every film in it to Processing at once, and each film changes to its
  result as its turn ends. **Stop** returns the films still waiting to their own status
  at once; the film in flight stays Processing until it finishes. A single run shows
  Processing on that film only, as before.
- The summary line keeps its three parts (STUDIES · UNSEGMENTED · TO REVIEW).
  UNSEGMENTED counts Unsegmented, Processing and Failed films.
- Sorting the Find list by STATUS orders the films Failed, Processing, Unsegmented, Needs
  review, Segmented, Reviewed.

## Failed

- **Failed** has its own red, `#B42318` in the light theme and `#F07167` in the dark
  theme. It used to share the terracotta of Needs review.
- The tooltip of a Failed pill, on the Find list and in the Analysis header, reads
  `Segmentation failed · <date>` (for example `Segmentation failed · Oct 2, 2026`) and,
  on the next line, the reason. A failure recorded before this release has no date, and
  its tooltip shows none: the date is never guessed.

## The Analysis screen

- While a film reads Failed, a red note under the Region and Orientation controls reads
  **Last run failed:** followed by the reason.
- A Failed film with no results whose Region is Lumbar, or whose original image cannot
  be shown (for example because the file was moved), shows a FAILED card where the "No
  segmentation yet" card would be: **Segmentation failed**, the reason, and **Run
  segmentation**. For other films the screen shows the original radiograph instead, and
  the red note gives the reason.
- As in 1.0.13, a successful run, or changing Region or Orientation, clears the failure.

## Plain reasons

The reason kept with a failed attempt is now a sentence a reader can act on. When the
message is technical text from inside the app, such as a socket error, it is replaced:

| What happened | Reason kept |
|---|---|
| The connection to the processing backend was lost | The processing backend stopped. Restart Spine Contour, then segment again. |
| The processing backend's response could not be read | The processing backend returned an unreadable response. Restart Spine Contour, then segment again. |
| The connection ended before a result arrived | Processing connection ended before a result was received. |
| The film is no longer at its saved location | The film was not found at its saved location. Run segmentation from its Analysis screen to choose its new location. |
| No message at all | Segmentation failed without a reason. |

Messages from the processing backend, such as the one for an inconclusive automatic film
detection, and errors reading the film file are kept as written. A reason is kept to at
most 500 characters. Toasts, including the closing toast of a batch, still show the
original message.

## Library

Each study can store one new optional value: the time of its failed attempt. Libraries
saved by 1.0.13 or 1.0.14 open unchanged; the library format version is the same. A
failure recorded before this release keeps its original text until the film is run
again.

## Known limitations

- If **Stop** is pressed just as a film's turn starts, while its file is still being read,
  that film can show its own status for a moment before it reads Processing.
- A film that already has results but whose latest re-run failed is offered by batch
  segmentation and then skipped by it, as in 1.0.13. Re-run it from its Analysis screen.

## Checks

The renderer unit tests pass on this release's code: 614, including new tests for the
reason text and the tooltip, the new statuses and their sort order, the Analysis header
and note, the saved time of a failure and what a failed run stores.

The automated checks in `tools/smoke/` drive the running app with real clicks. The five
that cover what this release changes each ran on a fresh profile and passed in full on
this release's code:

- `smoke-studies.mjs` (the Find list, batches and the Analysis screen): 151 of 151;
- `smoke-workspace.mjs` (the Workspace screen): 100 of 100;
- `smoke-persist.mjs` (saving and reopening): 41 of 41, then 53 of 53 after a restart;
- `smoke-parameters.mjs` (the Parameters tab and its exports): 58 of 58;
- `smoke-landing.mjs` (the welcome screen): 16 of 16.

Four of these checks predated 1.0.11's segmental columns in the paired export and
1.0.12's **Keep column name** option on the Workspace mapping card; they were updated to
expect that output. No app code changed for them.

The release was also checked on ten lateral films (copies), on an NVIDIA RTX 4070,
through the app's displayed text and stored state. Starting a batch turned all ten to
Processing at once, and Stop returned the waiting films at once. One film whose file had
been moved away read Failed with the file-not-found sentence and a dated tooltip; three
films for which automatic film detection was inconclusive read Failed with the backend's
sentence. The failures survived a restart, and setting one of those films' Region to
Lumbar cleared its failure, after which it segmented. This check ran before the 1.0.14
changes were merged in. No screenshots of films were taken.

## Installation

The release provides Windows x64 and macOS Apple Silicon installers plus
`SHA256SUMS`. In-app updating is not included; install the new version over the
existing app. Studies and settings remain in the existing application profile.
The macOS app remains unsigned.
